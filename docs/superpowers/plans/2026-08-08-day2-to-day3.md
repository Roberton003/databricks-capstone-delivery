# Day 2 → Day 3 Migration Plan

**Date:** 2026-08-08  
**Status:** Pre-migration planning  
**Target architecture:** Separated MCP server (FastMCP) + Flask dashboard + optional Agent Bricks

---

## Goal

Separate the Day 2 monolithic Flask app (`app.py`) into two distinct components:

1. **MCP Server** (`mcp_server/`) - FastMCP-based server exposing Alpaca Markets paper-trading functionality
2. **Flask Dashboard** (`dashboard/`) - Read-only UI for viewing watchlist, prices, and news

The migration preserves the existing Day 2 data layer (Lakebase + Massive API) while enabling new capabilities:
- Alpaca Markets paper-trading via MCP
- Agent Bricks integration (optional)
- Clear separation of concerns between data access and UI

### Phase 3: MCP Server Implementation

- [ ] **3.1** Create `mcp_server/alpaca_broker.py`
  - Purpose: Alpaca Markets API client for paper-trading
  - Methods:
    - `get_account()` - Get paper-trading account
    - `get_positions()` - Get current positions
    - `place_order(symbol, qty, side, type='market')` - Place order
    - `cancel_order(order_id)` - Cancel order
    - `get_orders()` - Get order history
  - Secret scope: `alpaca` (key: `api-key`, `secret-key`)
  - Base URL: `https://paper-api.alpaca.markets` (or production based on config)

- [ ] **3.2** Create `mcp_server/massive_broker.py`
  - Reuse: `massive_client.py` from Day 2 (import as module)
  - Methods (wrap existing):
    - `get_latest_price(symbol)` - Wrapper around `MassiveClient.get_latest_price()`
    - `get_news(ticker, limit=50)` - Wrapper around `MassiveClient.get_news()`
    - `get_watchlist()` - Query Lakebase `watchlist` table

- [ ] **3.3** Create `mcp_server/alpaca_mcp_server.py`
  - Purpose: FastMCP server entry point
  - Structure:
    ```python
    from fastmcp import FastMCP
    
    mcp = FastMCP("alpaca-markets")
    
    # Add MCP resources and tools here
    
    if __name__ == "__main__":
        mcp.run()
    ```
  - MCP Resources to expose:
    - `alpaca/account` - GET /account
    - `alpaca/positions` - GET /positions
    - `alpaca/orders` - GET /orders
    - `alpaca/places_order` - POST /orders
    - `alpaca/cancel_order` - DELETE /orders/{id}
    - `massive/price` - GET /v2/aggs/ticker/{symbol}/prev
    - `massive/news` - GET /v2/reference/news
  - Secret management: Use `mcp.context.settings` for API keys

- [ ] **3.4** Update `requirements.txt` with new dependencies
  - Add: `fastmcp>=0.1.0`, `alpaca-py>=0.2.0`
  - Keep existing: Flask, lakebase, massive_client dependencies

## Rollback Plan

If issues are discovered after deployment:

1. **Code rollback**:
   ```bash
   git checkout main
   git merge upstream-main  # or source branch
   databricks bundle deploy -t dev
   ```

2. **Secret preservation**:
   - Existing `massive` and `database` secrets remain intact
   - `alpaca` scope can be safely deleted: `w.secrets.delete_scope("alpaca")`

3. **Database schema**:
   - No schema changes in this migration
   - Existing tables (`watchlist`, `ticker_news_documents`, etc.) unaffected
